# 城市统计片区重划分摊服务

把旧网格（带整数户数的整数矩形）按矩形重叠面积，均匀估算分摊到新的统计片区，
用于跨年对比。FastAPI + SQLite 实现，支持整版版本提交、异步生成、快照隔离与原子发布。
并提供**片区合并供数**：对已发布结果按共边连通关系把户数过少的片区合并到达标分组。

## 业务规则

- 矩形为整数轴对齐矩形 `[x1, y1, x2, y2]`，要求 `x1 < x2`、`y1 < y2`，面积 `(x2-x1)*(y2-y1)`。
- 每次**整版提交**旧网格或新片区，每版最多 **12** 个条目；同版条目编号唯一、矩形**内部不得重叠**（边界相接允许）。
- 生成结果时，**任一旧格未被新片区完整覆盖则拒绝**该次生成；片区可以延伸到旧网格之外。
- 通过覆盖校验后，**逐格**按重叠面积分摊该旧格的整数户数：
  - 先按面积比例取整；
  - 余数用**最大余数法**分配，余数相同时按**片区编号升序**（可解析为整数的编号按数值升序，否则按字符串升序）。
- 分摊结果**总户数守恒**，并带守恒护栏；输出片区汇总及两份输入版本。
- 生成在后台串行执行。生成任务在创建的同一事务内**固定当时最新的 old/new 版本快照**，
  生成期间仍可替换任一输入（产生新版本），不影响进行中的任务。
- 当前结果在单事务内原子切换；新结果**完整发布前**，`/result` 始终返回上一份已发布结果；
  生成失败只标记任务，**不改变**已发布结果。

## 片区合并供数规则

年度资料库不希望把户数过少的片区单独作为统计单元，因此在已发布分摊结果之上提供合并供数：

- 统计员通过 `POST /merges` 设定**最低户数**（正整数）；输入固定为**当前已发布结果**的
  片区矩形与户数，合并任务在创建事务内**绑定该生成任务 id**（`source_generation_id`）。
- 两个片区仅当矩形共享一段**正长度的边**时相邻；**只在角点相接不算相邻**。
  所有片区先划入共边连通分量，合并组只能在分量内部形成。
- 每个合并组总户数必须达到门槛；在所有可行方案中选择**组数最多**者；
  组数并列时，按**组内编号升序、组列表升序**取字典序最小的唯一方案
  （编号可解析为整数时按数值升序，否则按字符串升序，与分摊模块一致）。
- 合并前后**总户数守恒**，且每个片区恰好归入一个组（带守恒护栏）。
- **无解**（某连通分量总户数仍低于门槛，或零户数孤立片区等）时任务落为 `failed`，
  `error` 点名涉及片区与原因，**不发布任何部分结果**。
- 源结果在合并计算期间被替换也不影响任务：输入始终按绑定的 `source_generation_id` 读取。
  重算成功前，供数入口 `GET /merge-result` 仍返回旧合并版但带 **`stale=true`** 标记，
  不会把旧合并版冒充为新版；对新结果重新发起合并并成功后才切换供数。
- 合并结果在**单事务内原子发布**（组明细 + 任务成功 + 供数指针切换）；
  写入失败随事务回滚，仍有效的上一合并版不受损坏。

## 目录结构

```
app/
  config.py       运行配置（DB 路径、每版上限）
  models.py       Pydantic 请求/响应模型
  allocation.py   纯函数：几何、覆盖校验、最大余数法分摊、汇总
  merging.py      纯函数：共边邻接、连通分量、达标分组最优化、无解与守恒护栏
  db.py           SQLite 持久化、版本快照、后台生成/合并与原子发布
  main.py         FastAPI 路由与单线程后台工作池
tests/            pytest 单元 + 集成测试（49 个用例）
Dockerfile
docker-compose.yml
```

## API 一览

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/old-grids` | 整版提交旧网格（编号、矩形、户数），产生不可变版本 |
| POST | `/new-districts` | 整版提交新片区（编号、矩形），产生不可变版本 |
| GET | `/versions?kind=old\|new` | 列出输入版本（历史版本保留） |
| GET | `/versions/{id}` | 查询单个版本 |
| POST | `/generations` | 开始生成（202），同步固定版本快照，后台计算 |
| GET | `/generations` | 列出全部生成任务 |
| GET | `/generations/{id}` | 查询任务状态：pending/running/succeeded/failed |
| GET | `/result` | 当前已发布结果（片区汇总 + 两份输入版本），无结果时 404 |
| POST | `/merges` | 发起片区合并供数（202），绑定当前已发布生成任务，后台计算 |
| GET | `/merges` | 列出全部合并任务（含失败原因与 stale 标记） |
| GET | `/merges/{id}` | 查询合并任务：成功时返回分组，源结果被替换时 stale=true |
| GET | `/merge-result` | 当前供数的合并版，无成功合并时 404；stale=true 表示源已更替 |
| GET | `/health` | 健康检查 |

## /docs 演示流程

1. `POST /old-grids` 提交旧网格；
2. `POST /new-districts` 提交新片区；
3. `POST /generations` 触发生成，记录返回的任务 `id`；
4. 轮询 `GET /generations/{id}` 直到 `succeeded`（覆盖不足时为 `failed`，`error` 给出原因）；
5. `GET /result` 查看片区汇总、逐格分摊明细与两份输入版本。
6. `POST /merges` 设定最低户数发起合并，记录返回的任务 `id`；
7. 轮询 `GET /merges/{id}` 直到 `succeeded`（无解时为 `failed`，`error` 说明原因）；
8. `GET /merge-result` 查看合并供数分组；若已发布更新的生成结果，响应带 `stale=true`，
   需对新结果重新发起合并。

### 合并请求示例

```json
// POST /merges
{"min_households": 3}
```

对一行四个相邻片区（户数依次 1、2、1、2），门槛 3 的最优方案为两组：
`[d1, d2]=3`、`[d3, d4]=3`，总户数 6 守恒。若把门槛设为 7（超过总户数 6），
任务 `failed`，`error` 指明“连通组总户数 6 低于最低户数 7”，且不发布部分结果。

### 请求示例

```json
// POST /old-grids
{
  "items": [
    {"id": "g1", "rect": [0, 0, 10, 10], "households": 7},
    {"id": "g2", "rect": [0, 10, 10, 20], "households": 11}
  ]
}
```

```json
// POST /new-districts（rect 也可写成 {"x1":..,"y1":..,"x2":..,"y2":..} 对象）
{
  "items": [
    {"id": "d1", "rect": [0, 0, 5, 20]},
    {"id": "d2", "rect": [5, 0, 10, 20]}
  ]
}
```

上例两个旧格在 d1/d2 上均为等面积（各 50%）：
`g1=7` 拆成 `4/3`、`g2=11` 拆成 `6/5`（余数并列时编号小的 d1 先得 +1），
片区汇总 `d1=10`、`d2=8`，总计 18，与输入总户数一致。
